# baize-agents 代码导读

面向 Python 初学者，逐个文件解释这个项目**为什么这么写**。

---

## 一、整体数据流

```
你敲命令
   │
   ▼
cli.py ── 解析参数、装配
   │
   ├─► config.py    读 config.json + .env，得到 provider 配置
   ├─► session.py   读出历史消息（JSONL）
   │
   ▼
runner.py           agent 循环
   │
   ├─► providers/openai_compat.py   发 HTTP 请求给模型
   │
   └─► tools/        模型要工具 → 执行 → 结果回喂
        │
        └─► 直到模型给出最终答案
   │
   ▼
cli.py ── 打印答案；session.py 把新消息追加落盘
```

**一句话**：`cli` 装配 → `config`/`session` 供料 → `runner` 循环 → `provider` 调模型 + `tools` 干活 → `session` 存档。

## 三、pyproject.toml

项目的「身份证 + 安装说明书」。`pip install` 读的就是它。

```toml
[build-system]
requires = ["setuptools>=68"]        # 打包用的工具（不是运行时依赖）
build-backend = "setuptools.build_meta"

[project]
name = "baize-agents"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = []                     # 运行时依赖：这里为空 = 纯标准库

[project.scripts]
baize = "baize_agents.cli:main"      # ← 装完生成 baize 命令，指向 cli.main()

[tool.setuptools.packages.find]
where = ["src"]                       # 代码在 src/ 下找（src 布局）
```

关键点：

| 段落 | 作用 |
|---|---|
| `[build-system]` | 用什么工具打包 |
| `[project]` | 我是谁（名字/版本/依赖） |
| `[project.scripts]` | 装完暴露什么命令 |
| `[tool.setuptools...]` | 源码在哪 |

`pip install -e .` 的 `-e`（editable）会写一个 `.pth` 指针文件，把 `src/` 加进 `sys.path`，所以**改代码不用重新安装**。

## 五、cli.py —— 命令行入口

**职责**：解析参数 → 装配 provider/session → 调 runner → 打印 + 存档。

```python
def _build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="baize", ...)
    parser.add_argument("-m", "--message", help="要发给模型的消息")
    parser.add_argument("-s", "--session", default="default", ...)
    parser.add_argument("--no-session", action="store_true", ...)
    parser.add_argument("-p", "--provider", default=None, ...)
    parser.add_argument("--list", action="store_true", ...)
    parser.add_argument("--clear", action="store_true", ...)
    return parser
```

`argparse` 像餐厅点单机：你声明菜单（有哪些参数），它负责把客人说的话翻译成结构化数据，还自动生成 `-h` 帮助。

主流程：

```python
if args.list:  ... return 0        # 不消耗模型
if args.clear: ... return 0
if not args.message: 报错

config = load_config(args.config)          # 读配置
provider = OpenAICompatProvider(config.get(args.provider))

session = None if args.no_session else Session(args.session)
session.load()                             # 读历史
session.add({"role": "user", "content": args.message})
session.sync()                             # 先落盘用户消息

try:
    reply = run(provider, session.messages, on_tool_call=_trace_tool_call)
finally:
    session.sync()                         # 补上 run 期间新增的消息
```

两个设计点：

1. **`finally` 里 sync**：即使 runner 中途失败，也把已经发生的对话存下来
2. **工具日志打到 stderr**：不污染 stdout 上的最终答案，方便管道处理（`baize -m ... > out.txt`）

## 六、config.py —— 配置加载

**职责**：读 JSON + `.env`，产出一个 `ProviderConfig`。

### 数据结构

```python
@dataclass(frozen=True)
class ProviderConfig:
    base_url: str
    model: str
    api_key_env: str | None = None
    api_key: str | None = None

    def resolve_api_key(self) -> str: ...     # 取 key + 校验

@dataclass(frozen=True)
class Config:
    providers: dict[str, ProviderConfig]
    default: str

    def get(self, name=None) -> ProviderConfig: ...
```

`@dataclass(frozen=True)` = 你只声明字段，Python 自动生成 `__init__`/`__repr__`/`__eq__`；`frozen` 表示创建后不可改。
**适合「主要工作是装数据」的类**。`ConfigError`/`ProviderError` 这类异常、以及 `OpenAICompatProvider` 这种服务类就不该用。

### 配置格式（两种都支持）

```json
// 多 provider（推荐）
{
  "default_provider": "deepseek",
  "providers": {
    "deepseek": {"base_url": "...", "model": "...", "api_key_env": "DEEPSEEK_API_KEY"},
    "ollama":   {"base_url": "...", "model": "...", "api_key": "ollama"}
  }
}

// 单 provider（旧格式，仍兼容）
{"provider": {"base_url": "...", "model": "...", "api_key_env": "..."}}
```

### `.env` 加载器


### 密钥校验

```python
def _validate_api_key(key: str, source: str) -> str:
    if any(ord(ch) > 127 for ch in key):   # 含中文（多半是占位符没换）
```

## 七、session.py —— 会话持久化

**职责**：把 `messages` 存进 JSONL 文件、再读出来。不碰模型、不碰工具。

### 为什么是 JSONL（每行一个 JSON）

| 好处 | 说明 |
|---|---|
| 追加写 | 新消息直接 append，不用重写整个文件 |
| 抗崩溃 | 写一半崩了，前面完整的行还在 |
| 好调试 | `cat` / `grep` 直接看 |
| 流式友好 | 可一行一行处理 |

### `_saved` 计数 —— 全文灵魂

```python
def __init__(self, name="default"):
    ...
    self._saved = 0     # 已经落盘的消息条数

def add(self, message):
    self.messages.append(message)          # 只进内存，不写文件

def sync(self):
    pending = self.messages[self._saved:]  # ← 切片：只取"欠账"部分
    if not pending:
        return                             # 没欠账就不动（幂等）
    self.path.parent.mkdir(parents=True, exist_ok=True)
    with self.path.open("a", encoding="utf-8") as f:
        for message in pending:
            f.write(json.dumps(message, ensure_ascii=False) + "\n")
    self._saved = len(self.messages)       # 记账
```

内存可以有 10 条、文件只有 6 条，`_saved=6` 记录「还欠 4 条」。
于是 `sync()` 只需**追加欠账的 4 条**，不重写前 6 条。重复调用结果一致（幂等）。

### `_repair` —— 崩溃自愈

问题：程序在「模型要了工具、但结果还没回喂」时崩了，文件里会留下：

```
{"role": "user", ...}
{"role": "assistant", "tool_calls": [{"id": "c1", ...}]}   ← 要了工具，没有对应结果
```

这种历史**直接发给 API 会报错**（OpenAI 要求 `tool_calls` 必须被配对回答）。

```python
def _repair(messages):
    for i in range(len(messages) - 1, -1, -1):        # 从后往前扫
        msg = messages[i]
        if msg.get("role") == "assistant" and msg.get("tool_calls"):
            needed = {c.get("id") for c in msg["tool_calls"]}
            answered = {
                m.get("tool_call_id")
                for m in messages[i + 1:]                  # 它后面有哪些回答
                if m.get("role") == "tool"
            }
            if not needed <= answered:                     # 集合子集判断
                return messages[:i]                        # 砍掉尾巴
            return messages
    return messages
```

> 为什么「最后一组完整 ⇒ 前面的必然完整」？因为消息按顺序追加，runner 一定把一轮的所有工具结果补完才进下一轮。所以**崩溃只可能影响末尾**。

### 其它防护

## 八、providers/ —— 调模型（4 个文件分工）

```
providers/
├── errors.py         错误分类（瞬态/限流/认证/欠费/上下文超长）
├── retry.py          RetryPolicy 退避计算 + retry_call 重试循环
├── base.py           Provider 抽象基类，重试逻辑集中于此
└── openai_compat.py  唯一的实现：只管「发一次请求」
```

### errors.py：为什么必须分类

不同错误的应对方式**完全不同**：

| 错误 | 状态码 | 该怎么办 |
|---|---|---|
| 网络抖动 / 超时 | — | 重试 |
| 服务端错误 | 5xx | 重试 |
| 限流 | 429 | 重试（优先听 `Retry-After`） |
| 认证失败 | 401 / 403 | **立即放弃** |
| 余额不足 | 402 | **立即放弃** |
| 上下文超长 | 400 + 特定码 | **立即放弃**（该压缩历史） |

分不清的后果：该重试的不重试（一抖动就挂），不该重试的疯狂重试（烧钱）。

分类靠一个类的属性 `retryable` 表达：

```python
class ProviderError(Exception):   retryable = False
class TransientError(ProviderError):  retryable = True
class RateLimitError(TransientError): # 额外带 retry_after
class AuthError(ProviderError):       # 不可重试
class QuotaError(ProviderError):      # 不可重试
class ContextOverflowError(ProviderError):  # 不可重试
```

`classify_http_error(status, body, retry_after_header)` 把状态码翻译成上面某一种。

### retry.py：把「算等多久」和「真的睡」分开

```python
@dataclass(frozen=True)
class RetryPolicy:
    max_attempts: int = 4
    base_delay: float = 1.0
    max_delay: float = 30.0
    jitter_ratio: float = 0.25

    def delay_for(self, attempt, error, jitter=0.0) -> float:
        if isinstance(error, RateLimitError) and error.retry_after is not None:
            return min(error.retry_after, self.max_delay)   # 听服务器的
        delay = min(self.base_delay * (2 ** (attempt - 1)), self.max_delay)
        return delay + delay * self.jitter_ratio * jitter     # 指数退避 + 抖动
```

设计要点：

- **纯函数**：`delay_for` 不睡、不做 IO，所以测试它不用真的等几秒
- **`sleep` 可注入**：测试时传一个假函数，记录「睡了几次、每次多久」
- **抖动（jitter）**：避免多个客户端同时醒来再一起撞服务器
- **`Retry-After` 优先**：服务器明确说了等多久就听它

```python
def retry_call(fn, policy, *, sleep=time.sleep, jitter=random.random, on_retry=None):
    attempt = 0
    while True:
        try:
            return fn()
        except ProviderError as e:
            attempt += 1
            if not e.retryable or attempt >= policy.max_attempts:
                raise                    # 不可重试 / 用完了
            delay = policy.delay_for(attempt, e, jitter())
            if on_retry: on_retry(attempt, e, delay)
            sleep(delay)
```

> 注意它**只捕 `ProviderError`**。如果代码有 bug 抛了 `ValueError`，会直接冒出去——这正是想要的：
> **不要用重试逻辑掩盖代码 bug。**

### base.py：抽象基类

```python
class Provider(ABC):
    @abstractmethod
    def _chat_once(self, messages, tools): ...   # 子类只管这个

    def chat(self, messages, tools=None):
        return retry_call(lambda: self._chat_once(messages, tools), self.policy, ...)
```

**子类只实现「发一次请求」，重试由基类包一层。** 好处：换实现（Anthropic 原生 / 本地模型）不用重写重试逻辑。

### openai_compat.py：只负责发请求

```python
def _chat_once(self, messages, tools=None) -> dict:
    url = f"{self.base_url}/chat/completions"
    payload = {"model": self.model, "messages": messages, "stream": False}
    if tools:
        payload["tools"] = tools
    ...
    try:
        with urllib.request.urlopen(request, timeout=120) as response:
            data = json.loads(response.read().decode("utf-8"))
    except urllib.error.HTTPError as e:
        body = e.read().decode("utf-8", errors="replace")
        raise classify_http_error(e.code, body, e.headers.get("Retry-After")) from e
    except urllib.error.URLError as e:
        raise TransientError(...) from e          # 连不上：可重试
    except (OSError, http.client.HTTPException) as e:
        raise TransientError(...) from e

    return data["choices"][0]["message"]         # 完整 message（可能含 tool_calls）
```

关键设计：

1. **只依赖标准库**（`urllib` + `json`），零第三方依赖，也让你看清 HTTP 请求长什么样
2. **返回完整 message 而不是只取 content** —— 判断「这是不是工具调用」是 runner 的活
3. **错误分类后就地抛出**，重试交给 base —— 职责单一

模型回复的三种形态：

```json
{"role": "assistant", "content": "好的"}                                    // 纯文本
{"role": "assistant", "content": "", "tool_calls": [{...}]}                 // 要工具
{"role": "assistant", "content": "...", "tool_calls": [{...}]}              // 两者都有
```

## 九、runner.py —— agent 循环（心脏）

**职责**：请求模型 → 有工具调用就执行 → 回喂 → 再请求，直到模型给出最终答案。

```python
def run(provider, messages, max_turns=10, on_tool_call=None) -> str:
    schemas = tools.get_schemas()

    for _ in range(max_turns):                       # 安全阀
        message = provider.chat(messages, tools=schemas)
        messages.append(message)

        if not message.get("tool_calls"):            # 没要工具 → 最终答案
            return message.get("content") or ""

        for call in message["tool_calls"]:           # 可能一次要多个
            name = call["function"]["name"]
            raw_args = call["function"]["arguments"] or "{}"
            try:
                arguments = json.loads(raw_args)
            except json.JSONDecodeError:
                result = f"[错误] 工具参数不是合法 JSON：{raw_args}"
            else:
                result = tools.execute(name, arguments)

            if on_tool_call:
                on_tool_call(name, raw_args, result)

            messages.append({                        # 回喂，必须带 id 配对
                "role": "tool",
                "tool_call_id": call["id"],
                "content": result,
            })

    raise RunnerError(f"超过最大轮数 {max_turns}")
```

四个设计决定：

| 决定 | 选择 | 理由 |
|---|---|---|
| 循环怎么停 | 没有 tool_calls 就返回；超 `max_turns` 抛错 | 防死循环 |
| 消息历史 | **就地修改**传入的 `messages` | 持久化直接复用这份列表 |
| 工具失败 | 转成文本回喂，不抛异常 | 让模型自己纠错，不崩 agent |
| 怎么观察循环 | 可选回调 `on_tool_call` | runner 保持 UI 无关 |

一圈的实际消息流：

```
第1轮  [user]
   →  assistant(tool_calls: c1)
第2轮  [user, assistant(c1), tool(c1, 结果)]
   →  assistant(最终答案)   ← 没有 tool_calls，返回
```

## 十、tools/ —— 工具层

### base.py：把「说明书」和「函数」绑在一起

```python
@dataclass(frozen=True)
class Tool:
    name: str
    description: str
    parameters: dict          # JSON Schema
    func: Callable[..., str]

    def schema(self) -> dict:
        return {"type": "function", "function": {
            "name": self.name,
            "description": self.description,
            "parameters": self.parameters,
        }}
```

绑在一起的好处：不会出现「说明书改了、函数没改」的错位。

`description` 是**给模型看的**——模型靠它决定「什么时候该用这个工具」，所以写得越清楚越好。

### file_read.py：安全地读文件

```python
def file_read(path: str) -> str:
    root = Path.cwd().resolve()
    raw = Path(path)
    target = (raw if raw.is_absolute() else root / raw).resolve()

    if not target.is_relative_to(root):              # 越界拦截
        raise ToolError(f"拒绝访问工作目录之外的路径：{path}")
    if not target.exists():  raise ToolError(...)
    if not target.is_file(): raise ToolError(...)

    size = target.stat().st_size
    if size > MAX_BYTES: raise ToolError(...)        # 防超大文件撑爆 context

    try:
        return target.read_text(encoding="utf-8")
    except UnicodeDecodeError as e:
        raise ToolError(f"不是 UTF-8 文本文件：{path}") from e
```

安全要点：

1. **限制在 cwd 内** —— 挡住 `/etc/passwd`、`~/.ssh/id_rsa`
2. **`.resolve()` 解析软链** —— 用软链指向目录外也会被挡
3. **限制文件大小** —— 防止把超大文件塞进上下文

### __init__.py：注册表 + 统一执行

```python
REGISTRY: dict[str, Tool] = {FILE_READ.name: FILE_READ}

def get_schemas():                        # 所有工具的说明书
    return [tool.schema() for tool in REGISTRY.values()]

def execute(name, arguments) -> str:      # 永远返回字符串
    tool = REGISTRY.get(name)
    if tool is None:
        return f"[错误] 未知工具：{name}"
    try:
        return tool.func(**arguments)
    except ToolError as e:
        return f"[错误] {e}"
    except TypeError as e:                # 参数不匹配
        return f"[错误] 调用 {name} 的参数不对：{e}"
    except Exception as e:                # 故意兜底
        return f"[错误] {name} 执行失败：{type(e).__name__}: {e}"
```

**`execute` 永不抛异常** —— 单个工具出错不会崩掉整个 agent 循环，而是把错误交给模型去处理。

想加新工具：写个文件 → 注册表加一行。

## 十一、一次问答的完整旅程

```
$ baize -m "pyproject.toml 的 version？"
│
├─ ① .venv/bin/baize             pip 生成的小脚本 → cli.main()
│
├─ ② cli.main()
│      argparse 解析：message / session / provider
│      load_config() → config.json + .env → ProviderConfig
│      Session("default").load() → 读出历史消息
│      session.add(用户消息); session.sync()          ← 先落盘
│
├─ ③ runner.run(messages)
│      schemas = tools.get_schemas()
│      ┌─ 循环 ────────────────────────────────────────┐
│      │ chat(messages, tools=schemas)                 │
│      │   → assistant(tool_calls: file_read)          │
│      │ 执行 file_read → 文件内容                      │
│      │ 追加 role="tool" 消息                          │
│      │ chat(messages, tools=schemas)  ← 带上结果     │
│      │   → assistant(最终答案)                        │
│      └───────────────────────────────────────────────┘
│
├─ ④ session.sync()              把新增的 assistant/tool 消息追加落盘
│
└─ ⑤ print(reply)
```

## 十三、设计决策速查

| 决策 | 选择 | 代价 |
|---|---|---|
| 依赖 | 纯标准库 | 代码略长，但零安装、可读性强 |
| provider 返回值 | 完整 message | 调用方要自己判断有无 tool_calls |
| 工具失败 | 转文本回喂 | 需要模型自己纠错 |
| 会话存储 | JSONL 追加 | 历史无限增长，需后续截断 |
| 配置兼容 | 新旧格式都支持 | 分支略多 |
| 工具沙箱 | 限 cwd + 限大小 | 合法需求也可能被挡 |

## 十四、已知限制（可继续迭代的方向）

1. **历史无限增长** —— 聊久了会撑爆 context，需要按 token 截断或摘要
2. **工具结果原样存** —— 读大文件会让历史暴涨
3. **无文件锁** —— 两个进程写同一会话会交错
4. **工具调用非 100% 触发** —— LLM 的随机性，可用 system prompt 引导
5. **只有 `file_read` 一个工具** —— 可加 `web_fetch` / `list_dir` / `file_write`
6. **非交互式** —— 每次都要敲 `-m`，可做 REPL
